# 配置工作流模块实现方案（Luban + Protobuf，独立可复用）

> 前置：《Excel+Protobuf配置数据工作流需求分析.md》
> 本文档把「Luban + Protobuf 配置工作流」设计成**独立模块**：自包含、不依赖任何具体项目代码，业务方通过**对外接口**接入。
> 命名空间统一 `ConfigFramework`，模块可整目录拷贝到任意 Unity 项目复用。
> 版本锁定：**Luban v4.9.0**（2026-05-28 发布，当前最新稳定 release）
> 标注 `[Luban生成]` 为 Luban 产物；其余为模块实现。

---

## 1. 模块定位与边界

| 项 | 说明 |
|---|---|
| **模块职责** | 配置的「加载 → 合并 → 缓存 → 访问 → 热更 → 重载通知」，以及 Editor 端 Luban 导出封装 |
| **不负责** | 具体业务数据含义、资源加载方式（通过 `IConfigSource` 抽象注入）、网络协议（用 `UnityWebRequest` 提供默认实现，可替换） |
| **依赖** | 仅 Unity 核心 + `Google.Protobuf`（运行时反序列化）；不依赖任何项目自定义类 |
| **Luban 位置** | 工具链层（生成代码 + 数据），不进入运行时依赖 |

---

## 2. 总体架构

```
策划 Excel 源表
   │  [Editor] ConfigExportTool（封装 Luban.ClientServer）
   ▼
Luban 产物：C# 强类型代码 + protobuf binary .bytes   [Luban生成]
   ▼
ConfigSystem（对外门面）
   ├─ 注册表加载器 RegisterTable<TTable>(...)     ← 屏蔽 Luban API
   ├─ 加载/合并：热更目录 > 内置（IConfigSource）  ← 可替换来源
   ├─ 缓存 + 强类型访问 GetTable<TTable>()
   ├─ 热更：manifest 对比 → 下载 → 原子替换
   └─ 事件：ConfigReloaded
   ▼
业务模块（只依赖 ConfigSystem 接口，不依赖内部实现）
```

```
ConfigFramework/
├── Runtime/
│   ├── ConfigSystem.cs              # 核心门面（对外主接口）
│   ├── ConfigSettings.cs            # 初始化参数

│   ├── ConfigHotUpdate.cs           # 热更（下载/替换/重载）
│   ├── IConfigSource.cs             # 加载来源抽象（扩展点）
│   └── StreamingAssetsConfigSource.cs # 默认来源实现
├── Editor/
│   └── ConfigExportTool.cs          # Luban 导出封装
└── (Luban 工作区，项目根或外部)
    ├── excel/  schema/  output/  gen.bat
```

## 4. 对外接口总览（核心）

所有外部调用都走 `ConfigSystem` 静态门面，业务方只需知道这几个接口：

| 类别 | 接口 |
|---|---|
| 初始化 | `ConfigSystem.Initialize(ConfigSettings)` |
| 注册表 | `ConfigSystem.RegisterTable<TTable>(tableName, deserializer)` |
| 加载 | `ConfigSystem.Load()` / `LoadAsync()` |
| 访问 | `ConfigSystem.GetTable<TTable>()` |
| 热更 | `ConfigSystem.CheckUpdate(onCompleted)` / `CheckUpdateAsync()` |
| 通知 | `ConfigSystem.ConfigReloaded` 事件 |

## 5. 核心组件设计

### 5.1 ConfigSettings（初始化参数）

```csharp
namespace ConfigFramework
{
    /// <summary>初始化参数。所有可替换项都通过这里注入，模块不硬编码路径。</summary>
    public class ConfigSettings
    {
        /// <summary>内置配置的加载来源（默认 StreamingAssets）。可注入自定义实现（AssetBundle/Addressables）。</summary>
        public IConfigSource Source = new StreamingAssetsConfigSource();

        /// <summary>内置配置子目录名（相对 Source 根，如 "Config"）。</summary>
        public string BuiltinDir = "Config";

        /// <summary>热更目录绝对路径。留空则用默认 persistentDataPath/ConfigPatch。</summary>
        public string PatchDir = null;

        /// <summary>远程 manifest 地址。留空则禁用热更（仅用内置）。</summary>
        public string RemoteManifestUrl = null;

        /// <summary>是否在加载后自动解析表间引用（Luban ref）。</summary>
        public bool AutoResolveRef = true;
    }
}
```

### 5.2 IConfigSource（加载来源抽象，扩展点）

```csharp
namespace ConfigFramework
{
    /// <summary>内置配置的读取来源。业务方可用 AssetBundle/Addressables/网络实现它注入。</summary>
    public interface IConfigSource
    {
        /// <summary>读取某张表的原始字节。找不到返回 null。</summary>
        byte[] Load(string tableName);

        /// <summary>读取内置 manifest（可返回 null，热更时用远程 manifest 兜底）。</summary>
        string ReadManifest();
    }
}
```

默认实现（读 StreamingAssets）：

```csharp
using System.IO;
using UnityEngine;

namespace ConfigFramework
{
    public class StreamingAssetsConfigSource : IConfigSource
    {
        public string SubDir = "Config";   // 由 ConfigSettings.BuiltinDir 覆盖

        public byte[] Load(string tableName)
        {
            string path = Path.Combine(Application.streamingAssetsPath, SubDir, tableName + ".bytes");
            return File.Exists(path) ? File.ReadAllBytes(path) : null;
        }

        public string ReadManifest()
        {
            string path = Path.Combine(Application.streamingAssetsPath, SubDir, "manifest.json");
            return File.Exists(path) ? File.ReadAllText(path) : null;
        }
    }
}
```

### 5.3 ConfigSystem（核心门面）

```csharp
using System;
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

namespace ConfigFramework
{
    /// <summary>配置系统对外门面。业务方只与它交互。</summary>
    public static class ConfigSystem
    {
        // ---------- 初始化 ----------
        static ConfigSettings _settings;
        public static bool Initialized { get; private set; }

        public static void Initialize(ConfigSettings settings)
        {
            _settings = settings ?? throw new ArgumentNullException(nameof(settings));
            Initialized = true;
        }

        // ---------- 注册表（屏蔽 Luban 反序列化 API） ----------
        static readonly Dictionary<Type, string> _tableNames = new();
        static readonly Dictionary<Type, Func<byte[], object>> _loaders = new();
        static readonly Dictionary<Type, object> _tables = new();

        /// <summary>注册一张表：表类型、表名（用于定位文件）、字节→表 的反序列化委托。</summary>
        public static void RegisterTable<TTable>(string tableName, Func<byte[], TTable> deserializer)
            where TTable : class
        {
            _tableNames[typeof(TTable)] = tableName;
            _loaders[typeof(TTable)] = bytes => deserializer(bytes);
        }

        // ---------- 加载 / 重载 ----------
        public static void Load() { LoadInternal(); }

        public static IEnumerator LoadAsync()
        {
            LoadInternal();
            yield break;
        }

        public static void Reload() { LoadInternal(); }

        static void LoadInternal()
        {
            if (!Initialized) throw new InvalidOperationException("ConfigSystem 未初始化");
            _tables.Clear();
            foreach (var (type, loader) in _loaders)
            {
                string tableName = _tableNames[type];
                byte[] bytes = ConfigHotUpdate.TryLoadPatch(_settings, tableName)   // 热更优先
                            ?? _settings.Source.Load(tableName);                    // 回退内置
                if (bytes == null) { Debug.LogWarning($"[Config] 缺少表 {tableName}"); continue; }
                _tables[type] = loader(bytes);
            }
            if (_settings.AutoResolveRef) ResolveAllRefs();
            ConfigReloaded?.Invoke();
        }

        // ---------- 数据访问 ----------
        public static TTable GetTable<TTable>() where TTable : class
        {
            return _tables.TryGetValue(typeof(TTable), out var t) ? (TTable)t : null;
        }

        public static bool TryGetTable<TTable>(out TTable table) where TTable : class
        {
            table = GetTable<TTable>();
            return table != null;
        }

        // ---------- 热更 ----------
        public static void CheckUpdate(Action<bool> onCompleted) => ConfigHotUpdate.CheckUpdate(_settings, onCompleted);
        public static IEnumerator CheckUpdateAsync() => ConfigHotUpdate.CheckUpdateAsync(_settings);

        // ---------- 事件 ----------
        /// <summary>加载/重载完成后触发。业务方订阅并重读配置。</summary>
        public static event Action ConfigReloaded;

        static void ResolveAllRefs()
        {
            // 遍历已加载表，调用各自 ResolveRef（Luban 生成表类提供，无则跳过）
        }
    }
}
```

> **便捷访问封装**（可选）：业务方为每张表加一层无字符串的静态包装：
> ```csharp
> public static class Configs
> {
>     public static TbWeapon Weapon => ConfigSystem.GetTable<TbWeapon>();
>     public static TbEnemy  Enemy  => ConfigSystem.GetTable<TbEnemy>();
> }
> ```

### 5.4 注册引导（屏蔽 Luban API 的唯一处）

```csharp
using ConfigFramework;

/// <summary>把 Luban 生成的表类注册进 ConfigSystem。生成代码更新后只改这里。</summary>
public static class ConfigBootstrap
{
    public static void Init()
    {
        ConfigSystem.Initialize(new ConfigSettings
        {
            RemoteManifestUrl = "https://your.cdn/config/manifest.json", // 或 null
        });

        // 反序列化方法名以 Luban 生成代码为准（示意用 Deserialize）
        ConfigSystem.RegisterTable<TbWeapon>("weapon", TbWeapon.Deserialize);
        ConfigSystem.RegisterTable<TbEnemy> ("enemy",  TbEnemy.Deserialize);
        ConfigSystem.RegisterTable<TbWave>  ("wave",   TbWave.Deserialize);

        ConfigSystem.Load();
    }
}
```

### 5.5 ConfigManifest（版本清单）

```csharp
using System;
using System.Collections.Generic;
using UnityEngine;

namespace ConfigFramework
{
    [Serializable]
    public class ConfigManifest
    {
        [Serializable]
        public struct Entry
        {
            public string Table;
            public string Hash;
        }

        public string Version;
        public List<Entry> Tables = new();

        public string ToJson() => JsonUtility.ToJson(this, true);
        public static ConfigManifest FromJson(string json) => JsonUtility.FromJson<ConfigManifest>(json);

        public bool Has(string table, string hash)
        {
            foreach (var e in Tables) if (e.Table == table && e.Hash == hash) return true;
            return false;
        }
    }
}
```

### 5.6 ConfigHotUpdate（热更）

```csharp
using System;
using System.Collections;
using System.IO;
using UnityEngine;
using UnityEngine.Networking;

namespace ConfigFramework
{
    public static class ConfigHotUpdate
    {
        static string PatchDir(ConfigSettings s) =>
            string.IsNullOrEmpty(s.PatchDir)
                ? Path.Combine(Application.persistentDataPath, "ConfigPatch")
                : s.PatchDir;

        /// <summary>热更目录命中且 hash 匹配才返回，否则 null（回退内置）。</summary>
        public static byte[] TryLoadPatch(ConfigSettings s, string tableName)
        {
            // 需配合 manifest 里该表的 hash 校验；简化：文件存在即用（完整校验见 CheckUpdate）
            string file = Path.Combine(PatchDir(s), tableName + ".bytes");
            return File.Exists(file) ? File.ReadAllBytes(file) : null;
        }

        public static void CheckUpdate(ConfigSettings s, Action<bool> onCompleted)
        {
            // 供协程/异步调用，此处从略（见 CheckUpdateAsync）
        }

        public static IEnumerator CheckUpdateAsync(ConfigSettings s)
        {
            if (string.IsNullOrEmpty(s.RemoteManifestUrl)) yield break;

            // 1. 拉远程 manifest
            using var req = UnityWebRequest.Get(s.RemoteManifestUrl);
            yield return req.SendWebRequest();
            if (req.result != UnityWebRequest.Result.Success) yield break;
            var remote = ConfigManifest.FromJson(req.downloadHandler.text);

            // 2. 对比本地，找差异表
            string localJson = s.Source.ReadManifest();
            var local = localJson != null ? ConfigManifest.FromJson(localJson) : null;

            foreach (var e in remote.Tables)
            {
                if (local != null && local.Has(e.Table, e.Hash)) continue;

                // 3. 下载差异表（URL 约定：manifest 同目录下 <Table>.bytes）
                string url = s.RemoteManifestUrl.Substring(0, s.RemoteManifestUrl.LastIndexOf('/') + 1) + e.Table + ".bytes";
                using var dl = UnityWebRequest.Get(url);
                yield return dl.SendWebRequest();
                if (dl.result != UnityWebRequest.Result.Success) continue;

                // 4. 原子替换
                SaveAtomic(s, e.Table, dl.downloadHandler.data);
            }

            // 5. 存新 manifest，触发重载
            Directory.CreateDirectory(PatchDir(s));
            File.WriteAllText(Path.Combine(PatchDir(s), "manifest.json"), remote.ToJson());
            ConfigSystem.Reload();
        }

        static void SaveAtomic(ConfigSettings s, string tableName, byte[] data)
        {
            Directory.CreateDirectory(PatchDir(s));
            string tmp = Path.Combine(PatchDir(s), tableName + ".bytes.tmp");
            File.WriteAllBytes(tmp, data);
            File.Replace(tmp, Path.Combine(PatchDir(s), tableName + ".bytes"), null);   // 原子覆盖
        }
    }
}
```

## 6. Luban 导出封装（Editor）

```csharp
#if UNITY_EDITOR
using System.Diagnostics;
using UnityEditor;
using UnityEngine;

namespace ConfigFramework.Editor
{
    public static class ConfigExportTool
    {
        /// <summary>导出参数：Luban 工作区路径 + 表结构目录 + Excel 目录 + 输出目录。</summary>
        public static void Export(string lubanDll, string rootDef, string excelDir, string codeDir, string dataDir)
        {
            string args = $"-j cfg -- -d \"{rootDef}\" --input_data_dir \"{excelDir}\" " +
                          $"--output_code_dir \"{codeDir}\" --output_data_dir \"{dataDir}\" " +
                          $"--gen_types code_protobuf3,data_protobuf_bin -s client";

            var psi = new ProcessStartInfo("dotnet", $"\"{lubanDll}\" {args}")
            {
                UseShellExecute = false,
                RedirectStandardOutput = true,
                RedirectStandardError = true,
            };
            using var p = Process.Start(psi);
            string log = p.StandardOutput.ReadToEnd() + p.StandardError.ReadToEnd();
            p.WaitForExit();

            if (p.ExitCode != 0) Debug.LogError("[ConfigExport] Luban 导出失败:\n" + log);
            else
            {
                Debug.Log("[ConfigExport] Luban 导出成功");
                AssetDatabase.Refresh();
            }
        }

        [MenuItem("Tools/Config/导出配置 (Luban)")]
        static void ExportFromMenu()
        {
            // 从项目约定读取路径后调用 Export(...)
        }
    }
}
#endif
```

## 7. 使用示例（接入方视角完整流程）

```csharp
using ConfigFramework;

public class GameEntry : MonoBehaviour
{
    void Awake()
    {
        // 1. 注册 Luban 表
        ConfigBootstrap.Init();          // 内部完成 Initialize + RegisterTable + Load

        // 2. 读配置
        var weapon = ConfigSystem.GetTable<TbWeapon>().Get(1001);
        Debug.Log($"weapon {weapon.Name} fireRate={weapon.FireRate}");
    }

    IEnumerator Start()
    {
        // 3. 检查热更（可选）
        yield return ConfigSystem.CheckUpdateAsync();
    }
}

public class WeaponManager : MonoBehaviour
{
    void OnEnable() => ConfigSystem.ConfigReloaded += Reload;
    void OnDisable() => ConfigSystem.ConfigReloaded -= Reload;

    void Reload()
    {
        // 重载后统一重读配置，避免持有旧引用
        var cfg = ConfigSystem.GetTable<TbWeapon>().Get(currentId);
        ApplyConfig(cfg);
    }
}
```

## 8. 扩展点汇总

| 扩展点 | 接口 | 用途 |
|---|---|---|
| 加载来源 | `IConfigSource` | 换 AssetBundle / Addressables / 网络，实现后注入 `ConfigSettings.Source` |
| 反序列化 | `RegisterTable<TTable>(...)` | Luban 生成 API 变化只改这里，门面不受影响 |
| 热更下载 | `ConfigHotUpdate`（可替换内部实现） | 需要特殊下载协议时替换 |
| 表间引用 | `AutoResolveRef` | Luban ref 外键解析开关 |

## 9. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 未初始化就 Load | 抛 `InvalidOperationException` |
| 缺表 / 反序列化失败 | 记日志 + 跳过该表，不崩整包 |
| 热更 hash 不符 | 回退内置；视为无效补丁 |
| 热更半写 | 临时文件 + `File.Replace` 原子覆盖 |
| 重载旧引用 | 业务方订阅 `ConfigReloaded` 重读，禁止长持有配置引用 |

---

## 10. 实施顺序

1. **M1**：建模块目录 → 装 `Google.Protobuf` + Luban → 1 张示范表跑通导出 → `ConfigSystem` + `ConfigBootstrap` 读到数据。
2. **M2**：落地 `IConfigSource` + `StreamingAssetsConfigSource`，运行时从 StreamingAssets 读 `.bytes`。
3. **M3**：`ConfigManifest` + `ConfigHotUpdate` 热更闭环 + 本地模拟热更。
4. **M4**：`ConfigExportTool` 编辑器一键导出 + 构建接入。
5. **M5**：校验增强、异常回滚、自定义 `IConfigSource` 示例。

## 11. 关键提醒

- **Luban 生成代码反序列化的确切 API**（`TbXxx.Deserialize(byte[])` 还是 `new TbXxx(byte[])`）以实际生成代码为准，本文档用 `Deserialize` 示意，落地时只改 `ConfigBootstrap`。
- **表间引用（ref）**：Luban 支持外键，需全部表加载完后统一 `ResolveRef`，否则跨表引用为 null。
- **模块独立性**：本模块不引用任何业务类型，唯一外部依赖是 `Google.Protobuf` 与 Luban 生成的表类（后者通过 `RegisterTable` 注入，属边界而非硬依赖）。
