# 机甲组件装配系统（AC Assembly）设计方案

> 项目：MNAC（迷你装甲核心）
> 对应 plans.md 中「Assembly（待定）」功能
> 本文档基于对现有代码的核对设计，复用项目已有挂点 / 装载 / 背包 / 黑板基础设施，**目标是把散落的装配机制统一为一套「部件 + 槽位 + 配置驱动」的组装框架**。
> 标注【现有】= 复用现有代码；【新设计】= 需新增实现。

---

## 1. 背景与目标

### 1.1 现状痛点

`HumanoidController.RequiredComponents` 采用**固定装配**：输入、UI、目标锁定、腿部、运动、左右手臂、武器背包全部写死在角色上，换部件需要改预制体/代码。

而项目已有的基础能力是**离散的**：
- 挂点 `MountPoint` 已能表达「左手武器 / 右手武器 / 小臂武器 / 胸部触发器」等装配位置（`MountPointLocation`）
- `ILoad`/`LoadBase` 已能描述「物体装载到挂点」的生命周期
- `WeaponBackpack` 已能按身体部位 + 武器名管理武器
- `ArmController` 已能从 `IArmDefinitions` 加载手臂的武器行为 + 动画定义
- `LegsController`/`LocomotionCore` 已能控制双腿 IK 与运动模块

但这些能力没有统一入口：装武器走背包、装手臂走 `ArmDefinitions_SO`、腿部写死在角色上，彼此独立、互不感知。

### 1.2 目标

借鉴《装甲核心》的「AC 组装」玩法，建立一套**组件装配系统**：

- **部件（Part）**：核心 / 手臂 / 腿部 / 武器 四类可装配件
- **槽位（PartSlot）**：由挂点定义的身体装配位
- **配置驱动（AssemblyDefinitions）**：一份配置描述「这台机甲装了什么」，运行装配器即可完成整机组装
- **新增机型 = 新增配置**，不改角色代码

## 3. 系统架构

```
AssemblyDefinitions_SO（整机配置：槽位 → 部件ID）
        │ PartAssembler（装配执行器）
        ▼
部件实例（ArmPart / LegPart / WeaponPart / CorePart）
        │ 装载到挂点（ILoad.WhenMounted）
        ▼
黑板 PartSlot 字段广播
        ▼
控制器消费：ArmController / LegsController / LocomotionCore / WeaponBackpack
```

### 3.1 部件类型（PartType）【新设计】

```csharp
public enum PartType
{
    Core,        // 核心：基础属性/能量/重量
    LeftArm,     // 左臂
    RightArm,    // 右臂
    LeftLeg,     // 左腿
    RightLeg,    // 右腿
    Weapon,      // 武器（挂到手臂/胸部挂点）
}
```

### 3.2 槽位（PartSlot）【新设计】

槽位把「挂点 + 部件类型 + 黑板字段」绑定在一起：

```csharp
[Serializable]
internal class PartSlot
{
    public PartType type;            // 该槽位接受什么部件
    public MountPoint mountPoint;    // 物理挂载点（复用现有 MountPoint）
    public Guid blackboardField;     // 装配结果广播到黑板哪个字段
}
```

槽位到挂点位置的映射（复用 `MountPointLocation`，需扩展新增手臂/腿部挂点）：

| 槽位 | MountPointLocation | 黑板字段 |
|---|---|---|
| Core | Blackboard_Main（扩展 Core） | Character_PartSlot_Core |
| LeftArm | Left_Arm（**扩展**） | Character_PartSlot_LeftArm |
| RightArm | Right_Arm（**扩展**） | Character_PartSlot_RightArm |
| LeftLeg | Left_Leg（**扩展**） | Character_PartSlot_LeftLeg |
| RightLeg | Right_Leg（**扩展**） | Character_PartSlot_RightLeg |
| LeftWeapon | Left_Hand_Weapon（现有） | Character_PartSlot_LeftWeapon |
| RightWeapon | Right_Hand_Weapon（现有） | Character_PartSlot_RightWeapon |

### 3.3 部件定义（PartDefinitions_SO）【新设计，载体复用 SO】

部件定义 = 部件 ID + 装配所需数据，**数据的消费方仍是现有控制器**：

```csharp
public abstract class PartDefinitions_SO : ScriptableObject
{
    public string partId;        // 对应配置表 ID（接 Excel→Protobuf 工作流）
    public PartType type;
    public GameObject prefab;    // 模型/表现
}

// 手臂部件：携带现有 IArmDefinitions（武器行为 + 动画），换臂 = 换 ArmDefinitions
public class ArmPartDefinitions_SO : PartDefinitions_SO
{
    public ArmDefinitions_SO armDefinitions;   // 复用现有
}

// 腿部部件：携带运动参数（速度/Boost/QB/Jump）+ 脚部 IK 配置
public class LegPartDefinitions_SO : PartDefinitions_SO
{
    public float moveSpeed;
    public float boostSpeed;
    public float quickBoostPower;
    public float jumpHeight;
    public float maxLoad;        // 载荷上限
    // ... 装载时注入 LocomotionCore 的运动模块参数
}

// 武器部件：携带武器名称，经 WeaponBackpack/WeaponManager 装配
public class WeaponPartDefinitions_SO : PartDefinitions_SO
{
    public string weaponName;    // WeaponManager 中的武器名
}
```

### 3.4 整机配置（AssemblyDefinitions_SO）【新设计】

一份配置描述整台机甲的装配：

```csharp
[CreateAssetMenu]
public class AssemblyDefinitions_SO : ScriptableObject
{
    public ArmPartDefinitions_SO leftArm;
    public ArmPartDefinitions_SO rightArm;
    public LegPartDefinitions_SO leftLeg;
    public LegPartDefinitions_SO rightLeg;
    public WeaponPartDefinitions_SO leftWeapon;
    public WeaponPartDefinitions_SO rightWeapon;
    public CorePartDefinitions_SO core;
}
```

未来可整体迁到 Excel→Luban→Protobuf 配置表（`assembly` 表），与配置工作流闭环。

### 3.5 装配执行器（PartAssembler）【新设计】

核心编排者，挂在角色上：

```csharp
internal class PartAssembler : HumanoidComponent
{
    public void Assemble(AssemblyDefinitions_SO assembly)
    {
        Disassemble();
        // 按序装配：核心 → 腿部 → 手臂 → 武器
        AssembleCore(assembly.core);
        AssembleLegs(assembly.leftLeg, assembly.rightLeg);
        AssembleArms(assembly.leftArm, assembly.rightArm);
        AssembleWeapons(assembly.leftWeapon, assembly.rightWeapon);
    }

    void AssembleLegs(LegPartDefinitions_SO def)
    {
        // 1. 从部件库实例化 prefab / 从黑板取腿部件
        // 2. LoadBase.WhenMounted(mountPoint) 装载到腿部挂点
        // 3. 注入 LocomotionCore 运动参数（moveSpeed / boostSpeed / jumpHeight）
        // 4. 注册到黑板 Character_PartSlot_LeftLeg
        // 5. LegsController 读取新定义，更新 Final IK 配置
    }
    // AssembleArms / AssembleWeapons / AssembleCore 同理
}
```

## 4. 控制器如何消费装配结果

装配不直接改控制器逻辑，而是通过**黑板广播 + 现有控制器订阅**衔接，控制器自身保持不变：

| 消费方 | 读黑板字段 | 响应 |
|---|---|---|
| `ArmController` | `Character_PartSlot_LeftArm/RightArm` | 重新加载 `ArmDefinitions_SO`（武器行为 + 动画），切换到新手臂行为 |
| `LegsController` + `LocomotionCore` | `Character_PartSlot_LeftLeg/RightLeg` | 应用腿部运动参数（速度/Boost/QB/Jump），更新 Final IK 权重 |
| `WeaponBackpack` + `WeaponManager` | `Character_PartSlot_LeftWeapon/RightWeapon` | 从背包取武器 → 装载到手臂挂点 → `ArmController.WeaponSwitchingState` 切换 |
| `WeaponSwitchingState` | 现有 `Character_Weapon_LeftArm_Armed` 等 | 武器切换状态机逻辑不变 |

**关键点**：`ArmController` 已在 `Initialize()` 中通过黑板读取 `IArmDefinitions`、通过 `FindMountPoint(place)` 找挂点、`RegisterMountPoints` 注册挂点——这些机制原样复用，装配系统只负责「在装配时把正确的定义挂到正确的槽位」。

## 5. 装配流程时序

```
启动/进组装界面
  │
  ▼
PartAssembler.Assemble(AssemblyDefinitions_SO)
  ├─ Disassemble()：卸载旧部件（ILoad.WhenUnmounted → 黑板注销）
  ├─ 核心部件：装配 + 属性注入
  ├─ 腿部部件：装配 + 运动参数注入（LocomotionCore 生效）
  ├─ 手臂部件：装配 + ArmDefinitions 注入（ArmController 生效）
  └─ 武器部件：背包取武器 + 挂载（WeaponSwitchingState 生效）
  │
  ▼
黑板 PartSlot 字段就绪 → 各控制器取用 → 整机可操作
```

## 6. 可视化设计

### 6.1 运行时机甲表现（装配即所见）

- 部件预制体装载到 `MountPoint` 后，模型即时挂载到对应身体部位（复用 `LoadBase.WhenMounted` 设置 localPosition，`Arms/MountPoint.cs` 已有的 `_left`/`_right` 命名逻辑原样保留）
- **空槽位占位**：未装部件的槽位显示半透明轮廓 / 虚线框，标明"可安装"
- **换件过渡**：卸载旧模型 + 装载新模型时叠加 DOTween 淡入淡出，避免硬切

### 6.2 装配界面（Assembly UI）

接入现有 UI 体系（MNAC.UI / UICore），组装界面包含：

| 模块 | 功能 |
|---|---|
| **3D 机甲预览** | 独立预览相机 + 旋转 / 缩放查看；按槽位高亮对应挂点，点击部件高亮其安装位置 |
| **槽位面板** | 核心 / 左臂 / 右臂 / 左腿 / 右腿 / 左武器 / 右武器，每槽显示当前部件缩略图 + 名称 |
| **部件库** | 按 `PartType` 筛选浏览；部件卡片展示属性（移速 / 推进 / 跳跃 / 载荷 / 武器数据）；标注挂点兼容性 |
| **属性对比** | 当前装备 vs 候选部件的数值 diff，优 / 劣用红绿标注 |
| **约束校验** | 总重 ≤ 腿部 `maxLoad`、槽位类型匹配；超载 / 不匹配即时提示并禁用确认 |
| **确认装配** | 调用 `PartAssembler.Assemble(assembly)`，预览与角色即时生效 |

### 6.3 黑板状态可视化（运行时调试）

- **调试面板**：枚举黑板 `Character_PartSlot_*` 字段，显示每个槽位当前部件 ID / 名称
- **消费方状态**：`ArmController` 当前行为、`LegsController` 运动参数、当前武器，随装配实时刷新

### 6.4 编辑器工具

- **`PartAssembler` 自定义 Inspector**：槽位 ↔ 挂点绑定列表、当前装配配置、一键 Assemble / Disassemble 按钮
- **Scene Gizmos**：按槽位类型着色绘制挂点（手臂 = 蓝、腿 = 绿、武器 = 红、核心 = 黄），连线表示部件归属
- **`AssemblyDefinitions_SO` 定制 Inspector**：部件引用 + 属性摘要，装配前即可预览整机数值

### 6.5 可视化数据流（配置 → 表现）

```
AssemblyDefinitions_SO / 配置表
  → PartAssembler.Assemble()
  → 部件模型装载到 MountPoint（运行时表现）
  → 黑板 PartSlot 广播 → 控制器切换行为（ArmController / LegsController / WeaponBackpack）
  → UI 订阅黑板刷新槽位面板 / 属性对比
  → 调试面板 / Editor 工具读取同一黑板状态（可视化与逻辑同源）
```

## 7. 扩展性示例

| 需求 | 做法 |
|---|---|
| 换腿部（轻装/重装） | 换 `LegPartDefinitions_SO` → 运动参数不同，逻辑不变 |
| 换手臂（发射器手/剑手） | 换 `ArmPartDefinitions_SO` → `ArmDefinitions` 不同，行为随换 |
| 换武器 | 换 `WeaponPartDefinitions_SO.weaponName` → 背包重新装配 |
| 新增机型（如敌方 AC） | 新增一份 `AssemblyDefinitions_SO` + 部件定义，复用同一套 `PartAssembler` |
| 属性/平衡调整 | 走 Excel→Protobuf 配置，热更生效 |
