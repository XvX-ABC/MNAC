## 版本一：标准版

**MNAC（迷你装甲核心）** — Unity 3D 第三人称动作射击游戏
技术栈：C# / URP / Input System / Playables API / Final IK / Behavior Designer

类《装甲核心》的第三人称 3D 动作射击游戏，从零设计泛型分层状态机、组件化武器、两层运动、Playables 动画封装等核心框架，覆盖角色控制、手臂/武器行为、运动、交互影响、AI 全链路；程序集划分 + ScriptableObject 数据驱动。

1. **泛型分层状态机框架**：`StateMachineBase<TState,TContext>` 起步，向上扩展出混合过渡（固定退出时间 / 起始偏移 / 打断）、回调（OnEnter/OnUpdate/OnExit）与分层子状态机；同一套逻辑提供类 / Mono / ScriptableObject 三种载体
2. **组件化 + 数据驱动武器框架**：`IWeapon → Weapon` 抽象基类，发射器内置 Idle/DelayLaunch/Launching/Reload 状态机 + 对象池 `ProjectilePool<T>`，剑用刀尖触发器判定；ScriptableObject 驱动，组件可在运行时/编辑器增减以变更行为
3. **两层运动系统**：物理层 `LocomotionCore` 责任链（`ILocomotionModule` + 共享 Context，按优先级插入、高优先级覆盖）+ 人形层 `LocomotionStatemachine`（地面/跳跃/空中/爆发推进/旋转）；Final IK 脚部地面适应
4. **Playables API 动画封装**：`AnimationPlayablePartBase` + `AnimationPlayablePartTree : MTree` + `OutputSetting` 权重控制，把繁琐的节点链接/权重调整简化为树节点的增删
5. **手臂行为框架**：`IArmedArmBehaviour → ArmedArmBehaviourBase`，发射器行为基于 Final IK 持枪瞄准 + 动画丝滑过渡，剑行为按肢体动作激活武器功能；新增武器只需新增行为模块
6. **模块化角色装配 + AI 接管**：`HumanoidController` 通过 `RequiredComponents` 装配，AI 仅替换输入与目标锁定模块即可接管角色（Behavior Designer 行为树）
7. **配置数据加载/热更框架（ConfigFramework）**：自研独立可复用模块，`ConfigSystem` 门面 + 强类型注册表访问；`IConfigSource` 加载来源抽象（可换 AssetBundle / Addressables）；manifest 按表 hash 差异对比 + 差异下载 + 原子替换（临时文件 rename）+ `ConfigReloaded` 重载通知
8. **工程化**：按 asmdef 划分独立程序集（States/Animation/Interaction/TPhysics/UI/Utilities/Weapon/ConfigFramework），并配 NUnit 单元测试（运动模块优先级、工具类）

## 版本二：详细版

**项目名称**：MNAC（迷你装甲核心）—— Unity 3D 第三人称动作射击游戏
**技术栈**：C# / URP / Input System / Playables API / Final IK / Behavior Designer / DOTween

**一、项目背景**
借鉴《装甲核心》玩法，目标是在 Unity 中落地一款第三人称 3D 动作射击游戏，覆盖"输入 → 运动/瞄准 → 武器 → 命中影响"全链路。核心框架均从零设计：状态机、组件化武器、运动控制、动画封装、手臂行为、角色装配与配置加载/热更框架。

**二、主要职责**
- 设计并实现泛型分层状态机框架，支撑角色/运动/武器/手臂全部状态逻辑
- 设计组件化 + ScriptableObject 数据驱动的武器框架（发射器 / 剑 / 投掷物）
- 实现两层运动系统（物理责任链层 + 人形状态机层）与脚部地面适应
- 封装 Playables API 动画控制树，简化动态动画切换
- 设计手臂行为框架与模块化角色装配，实现 AI 对角色控制的接管
- 设计并实现独立的配置数据加载/热更框架（ConfigFramework），支持强类型访问与运行时热更
- 划分程序集边界并编写单元测试

**三、技术难点与解决**
1. **状态机扩展性与复用**：角色/运动/武器/手臂四处都要状态机，若各自写死难复用 → 全泛型设计 `StateMachineBase<TState,TContext>`，向上分层扩展出混合过渡、回调、子状态机；同一套逻辑以类/Mono/ScriptableObject 三载体复用
2. **过渡体验打磨**：普通切换生硬 → `BlendingTransition<T>` 参考 Unity 混合过渡实现固定退出时间、起始偏移、打断，实现丝滑过渡
3. **武器可扩展性**：武器行为/特效若写死难以变更 → 组件化设计，`Launcher`/`Sword` 由多个组件装配，运行时或编辑器环境下增减组件即可快速变更行为/特效；发射器内部状态机 + 对象池管理子弹
4. **运动逻辑分层**：物理与环境交互 vs 人形行为混在一起 → 拆两层，物理层 `LocomotionCore` 用责任链模式（共享 Context、按优先级插入模块、高优先级覆盖），人形层用状态机驱动（地面/跳跃/空中/爆发推进/旋转）
5. **动画控制繁琐**：Playables API 原生链接与权重调整繁琐 → 封装 `AnimationPlayablePartBase` 节点树，向节点增删子节点即添加/移除可播放部分，权重经 `OutputSetting` 快速设置
6. **AI 接入成本**：AI 复用玩家控制需避免重写 → `HumanoidController` 高度模块化装配，AI 仅替换输入与目标锁定模块即可接管角色，行为决策用 Behavior Designer 行为树
7. **配置规模化与热更**：配置数量多、需支持运行时改数值而不发版 → 自研独立模块 ConfigFramework，`IConfigSource` 抽象加载来源，manifest 按表 hash 差异对比，临时文件 rename 原子替换防半写，重载走 `ConfigReloaded` 事件通知业务方统一重读

**四、项目成果**
- 完成核心框架：泛型分层状态机、组件化武器、两层运动、Playables 动画封装、手臂行为
- 可玩 demo：基础运动（地面/跳跃/空中/爆发推进/手臂旋转）与发射器、剑两类武器，含瞄准、换弹、切枪、目标锁定
- 独立可复用的配置加载/热更框架（ConfigFramework），不依赖具体业务代码、可整目录移植
- 从零搭建的架构经受住两版大框架迭代，模块边界清晰、可按程序集独立编译与测试

## ⚠️ 诚实提示（非简历正文）

1. **完成度**：多数系统为**早期骨架**（已搭框架、未深入完善）。按 plans.md 进度：运动（地面/跳跃/空中/QB/手臂旋转）与武器直击/Missile 已完成；**Knife、Arts 待定，AI、Assembly、Mission 未开始**。

2. **AI**：目前仅完成 AI 对角色控制的接管（输入/目标锁定模块替换）+ 初步 Behavior Designer 行为树，行为决策逻辑未完善。简历中 AI 条目应弱化为"实现 AI 接管角色控制的模块替换方案 + 初步行为树"。

3. **配置工作流（ConfigFramework）**：运行时框架已实现于 `Assets/Scripts/ConfigFramework/`（`ConfigSystem` 门面、`ConfigHotUpdate` 热更、`ConfigManifest` 清单、`IConfigSource` 加载抽象、`ConfigExportTool` 导出封装），是独立可复用的 asmdef 模块。但 **Luban 工具链集成未完成**：`ConfigBootstrap` 在 `#if LUBAN_ENABLED` 宏后、引用的 `TbWeapon.Deserialize` 等为示意，Google.Protobuf 与 Luban 生成代码均未引入（`Packages/manifest.json` 无 protobuf/luban）。简历写"自研配置加载/热更框架"完全属实；若写"Excel→Luban→Protobuf 全链路跑通"则需先完成 Luban 集成。

4. **已知问题（如实，勿在简历主动罗列）**：剑冲刺结束后角色"踩空"下落、剑挥砍因角度/动画打不中目标、发射器手臂瞄准有几率不准（切武器后恢复）、AI 接入后角色意外旋转。
