### A.2 LocomotionCore 装配 API 现状

文件：`Assets/Scripts/TPhysics/Locomotion/LocomotionCore.cs`

现状要点：
- 内部维护**两条并行数组**：`ILocomotionModule[] _modules` 与 `Wrapper[] _moduleWrappers`。
- `Wrapper`（私有 struct）持有 `module`、`state`、`stepNum`；`state` 是私有枚举 `ModuleState{Ready,Started,Update,Ended}`，**只写不读，属于死代码**。
- `Wrapper.Update(Context)` 用一个 `stepNum` 状态机（0→Start, 1→Update, 2→End）驱动生命周期；禁用中的模块在 stepNum==1 时被切到 2，下次执行 End。
- 公开入口：
  - `AddModule(module, enabled=false)`：**只** `_moduleWrappers = _moduleWrappers.Append(w)`，**不更新 `_modules`**。
  - `AddModule_InsertByPriority(module, enabled=false)`：首次同时初始化两条数组；后续按 `Priority` 二分插入，**两条数组同时维护**（这是唯一保持同步的路径）。
  - `RemoveModule(module)`：只删 `_moduleWrappers`；删到空时把 `_moduleWrappers` 置 null，但 `_modules` 保持陈旧。
  - `EnableModule / DisableModule`：通过 `_moduleWrappers[index].module.Enabled` 改模块对象的 Enabled（因为 module 是引用类型，安全）。
  - `Contains / IndexOf`：基于 `_moduleWrappers`。
  - `Modules`（公开只读）：`Array.AsReadOnly(_modules)`，**读的是 `_modules`**。
- `Update()`：先 `_context.Synchronise()`，遍历 wrappers 逐个 `Update` 并写回（保留 stepNum），最后 `_context.Apply()`。
- 依赖 `MNAC.Utilities.Extensions.ArrayExtensions` 的 `Append/Insert/Remove` 扩展（每次操作都在重建数组；另有一个 `[Obsolete] Append(ref T[], T)` 重载）。

### A.3 双入口 / 双数组不同步 —— 验证结论（确定缺陷）

| 场景 | 结果 | 影响 |
|---|---|---|
| 只用 `AddModule` 后再读 `Modules` | `_modules` 仍为 null → `Array.AsReadOnly(null)` 抛 `ArgumentNullException` | 崩 |
| `AddModule` 后再 `AddModule_InsertByPriority` | InsertByPriority 首次调用初始化 `_modules` 只含**新**模块，漏掉之前 AddModule 的模块 | 清单不一致 |
| `RemoveModule` 删到空 | `_moduleWrappers = null`，但 `Modules` 仍返回旧 1 元素 | 幽灵模块 |
| `RemoveModule` 删中间项（>1） | `_modules` 仍包含被删模块 | 幽灵模块 |
| 只用 `AddModule_InsertByPriority` | 两条数组一致 | 正常 |

**结论**：`_modules` 与 `_moduleWrappers` 双数组是缺陷根源；`AddModule`/`RemoveModule` 是坏路径，`AddModule_InsertByPriority` 是唯一好路径。修复方向 = **只保留一条数据源**（见 C.5）。

## B. 问题清单

### B.1 装配易错点
1. **双入口**：`AddModule` vs `AddModule_InsertByPriority` 语义不一致（append vs 按优先级插入），调用者必须知道该用哪个。
2. **双数组不同步**：A.3 已验证，是确定性缺陷。
3. **Priority 语义隐晦**：默认全 0 → 等价插入顺序；`FindIndexByPriority` 对同优先级稳定（后插入者靠后），但无文档；`AddModule_InsertByPriority` 中 `if (idx == -1)` 是死分支（二分查找返回值恒 ∈ [0, len]）。
4. **装配是纯代码**：无可视化，用户要手写一串 `new Xxx(...)` + `AddModule`，易漏 `enabled`、顺序、VerticalPostureEvaluator 必须排最前等约定。
5. **模块构造参数散落**：各模块构造签名不一致，无统一"默认值 + 面板编辑"路径。

### B.2 测试空白
- 生命周期：Start→Update→End 顺序、禁用跳过 Start、运行中禁用触发 End、重新启用。
- LocomotionCore 与 Rigidbody 的 Synchronize/Apply 回路。
- GroundDetector 的碰撞语义（Enter/Stay/Exit、掩码、坡度阈值、加权法线、探针距离）。
- 各行为模块的数值行为（加速钳制、跳高、贴地投影、转向、drag 过渡）。
- 双数组同步回归（当前测试根本没测到 `Modules` 与内部一致性）。

### B.3 可测性障碍
1. **无 MonoBehaviour 宿主 / 无场景**：LocomotionCore、GroundDetector 都需外部喂数据；没有现成 Runner 把三者接起来。
2. **`Time.deltaTime` 硬编码**：HorizontalLocomotion/Boosting/Rotation/Jump/MutativeDrag 直接读 `Time.deltaTime`，纯逻辑断言不可确定。缓解：HorizontalLocomotion 在 `acceleratedSpeed==0` 分支不依赖 deltaTime（可直接断言钳制）；其余需 PlayMode 或后续注入 deltaTime。
3. **`Physics.Raycast` / `Collision` 无法在纯 C# 构造**：GroundDetector.GroundDistance 与 OnCollisionEnter/Stay/Exit 依赖真实物理；`Ground.TryCreate(Collision,…)` 是 internal static，只能 PlayMode 或反射测。
4. **测试程序集只有 EditMode**：`MNAC.TPhysics.Tests` includePlatforms 只有 Editor，无法承载 PlayMode 物理测试，需要新 PlayMode asmdef。
5. **`Modules` 双数组**：读 `_modules` 与写入路径不一致，测试本身容易踩雷。

## C. Editor 可视化装配目标设计

### C.1 要可视装配的字段
目标：在 Inspector 里可视化完成**模块实例清单**的增删、排序、启停，以及**每个模块各自的参数**。

- 清单级：模块类型 + 顺序（= 执行顺序）+ Enabled（启停）。
- 参数级（各模块可编辑字段）：
  - HorizontalLocomotion：MaxSpeed、AcceleratedSpeed、DirectionVector。
  - BoostingLocomotion：继承的三个字段。
  - JumpLocomotion：Height。
  - RotationByMouseOrTargetLocomotion：Camera（引用）、MouseScreenPosition（通常运行时给）、Target（引用）。
  - MutativeDrag：TransitionalDuration、Range(Vector2)。
  - VerticalPostureEvaluator：SampleQuantity（Priority 仅作排序提示，可选）。
  - StopLocomotion / StopRotation：无参数。

### C.2 序列化可行性矩阵 + 改造清单

Unity `[SerializeReference]` 要求：类型 `[Serializable]`；Editor 的"Add 模块"下拉要求**无参构造**。当前全部模块都不满足，逐项改造如下：

| 模块 | 现状可序列化 | 障碍 | 改造 |
|---|---|---|---|
| HorizontalLocomotion | _direction/_maxSpeed/_acceleratedSpeed 全可序列化 | 无 [Serializable]、无无参 ctor | +[Serializable]，+无参 ctor，字段改 public 属性（已有 setter 即可） |
| BoostingLocomotion | 继承字段 | 同上 | +[Serializable]，+无参 ctor |
| JumpLocomotion | _height 可序列化 | `_timeline`（Timeline 类型，非 Serializable，readonly，ctor 内 new） | `_timeline` 改 `[NonSerialized]` + 懒初始化（首次 OnStart 时 new）；+[Serializable]+无参 ctor |
| RotationLocomotion | 全可序列化 | internal 类，跨程序集 Editor 不可见 | 保持 internal，不直接装配（由装饰器内部 new） |
| RotationByMouseOrTargetLocomotion | _mouseScreenPosition、Camera 可序列化 | `_target`（IPositionTarget 接口不可直接序列化）、`_base`（readonly internal RotationLocomotion） | `_base` 改 `[NonSerialized]` + 懒初始化；`_target` 用 `[SerializeReference]` 承载具体实现，或声明为 UnityEngine.Object 引用；+[Serializable]+无参 ctor |
| StopLocomotion | 无字段 | 无 [Serializable] | +[Serializable]（已有隐式无参 ctor） |
| StopRotation | 无字段 | 同上 | +[Serializable] |
| MutativeDrag | _transitionalDuration/_range 可序列化 | `_timeline`（readonly，ctor 内 new）、`_rbody`（运行时 Rigidbody） | `_timeline` 懒初始化 + `[NonSerialized]`；`_rbody` 标 `[NonSerialized]`；+[Serializable]+无参 ctor |
| VerticalPostureEvaluator | SampleQuantity 逻辑量 | `_samples`（Vector3[] 运行时缓冲）、`_head` | `_samples/_head` 标 `[NonSerialized]`，把 sampleQuantity 存为独立可序列化字段（SampleQuantity getter 不再依赖数组长度）；+[Serializable] |

**通用要求**：所有可装配模块 +[Serializable]、提供无参构造、运行时/非序列化对象统一 `[NonSerialized]` + 懒初始化。Timeline 本身**不要**为了序列化而改（它是运行时状态机，含 delegate/executor）。

### C.3 承载形态与程序集归属（关键决策）

原则：基石库 `MNAC.TPhysics` 保持**纯 C#、无 MonoBehaviour、无 Editor**，不被装配宿主污染。

| 组件 | 放哪 | 理由 |
|---|---|---|
| Runner（MonoBehaviour，持 `[SerializeReference] List<ILocomotionModule>`，喂给 LocomotionCore） | **新建运行时程序集** `MNAC.Demo`（如 Assets/Scripts/Demo/） | 不在基石库加 MonoBehaviour；Runner 是"消费方" |
| Editor 面板 / PropertyDrawer | **新建 Editor 程序集** `MNAC.Demo.Editor`（Assets/Scripts/Demo/Editor/） | Editor 代码不能进运行时程序集；必须自有 asmdef 才能引用自定义运行时 asmdef（Assembly-CSharp-Editor 无法引用 asmdef 代码） |
| 模块本体 [Serializable] 改造 | 仍在 `MNAC.TPhysics` | 模块是基石库资产，只加序列化标注，不加宿主 |

### C.4 面板结构草图（纯文本）

`LocomotionRunner : MonoBehaviour`（运行时程序集 MNAC.Demo）：
```
[SerializeField] Rigidbody targetRigidbody;        // 或 Awake 时 GetComponent 兜底
[SerializeField] EnvironmentSettings environmentSettings;   // 复用已 [Serializable] 的配置
[SerializeReference] List<ILocomotionModule> modules = new();
LocomotionCore Core;                              // Awake/OnEnable 时由 modules 构建

void Awake()/OnEnable():
    var world = new World(Vector3.up, Physics.gravity);   // 或从 environmentSettings.WorldUp 推导
    var gd = new GroundDetector(environmentSettings, world);
    Core = new LocomotionCore(new Locomotion.Context(world, new TPhysics.Context(rb), gd));
    Core.SetModules(modules);                      // 顺序 = 面板顺序
void FixedUpdate():
    gd.Position = rb.position;  gd.OnFixedUpdate();
    Core.Update();
```

`LocomotionRunnerEditor : Editor`（Editor 程序集）：
```
OnInspectorGUI:
  1. 常规字段：targetRigidbody、environmentSettings
  2. ReorderableList 绑定 serializedProperty "modules"（SerializeReference 列表）
     - 每个元素 header：显示具体类型名 + 启用 toggle（读写 module.Enabled）
     - drawElement：用 Editor.CreateEditor(该 ILocomotionModule 实例) 内联渲染其字段
     - 支持拖拽排序（= 执行顺序）
  3. "Add Module" 按钮：反射/TypeCache 收集所有 concrete [Serializable] ILocomotionModule 子类，
     弹出下拉，选择后向 list 添加 managed reference 实例
  4. "Sort by Priority" 按钮（可选）：按 Priority 稳定排序（runtime 不自动排序）
```

实现要点/坑：
- SerializeReference 列表用 ReorderableList 时，增删改后要 `serializedObject.ApplyModifiedProperties()` + `EditorUtility.SetDirty`。
- managed reference 的"新增实例"要调用 `property.InsertArrayElementAtIndex` + `property.GetArrayElementAtIndex(i).managedReferenceValue = newInstance`，不能直接 new 后 Add。
- 模块字段渲染优先用 `Editor.CreateEditor(module)`（自动覆盖所有 public 可序列化字段），比逐个 PropertyDrawer 省事；若想要 Range/标题美化，再给个别模块加自定义 PropertyDrawer（**非必需**）。
- 自定义 PropertyDrawer 需求：**最小集不需要**；可选加分项 = 给 RotationByMouseOrTarget 的 Camera 引用、给 EnvironmentSettings 已有 Range/LayerMask 就够。

### C.5 LocomotionCore API 收敛设计

目标：单一装配入口 + 单一数据源 + 顺序即清单顺序。

建议签名：
```csharp
public class LocomotionCore
{
    public LocomotionCore(Context context);                        // 保留
    public LocomotionCore(Context context, IEnumerable<ILocomotionModule> modules); // 可选便捷构造

    public void SetModules(IEnumerable<ILocomotionModule> modules); // 唯一装配入口，全量替换，顺序=执行顺序
    public IReadOnlyList<ILocomotionModule> Modules { get; }        // 从单一数据源投影，不再读 _modules

    public void EnableModule(ILocomotionModule module);             // 保留（Runner 运行时启停用）
    public void DisableModule(ILocomotionModule module);            // 保留
    public bool Contains(ILocomotionModule module);                 // 可选保留
    public void Update();                                           // 不变
}
```

删除项：
- `AddModule`、`AddModule_InsertByPriority`、`RemoveModule`、`IndexOf`（公开）、`_modules` 数组、`FindIndexByPriority`。
- `Wrapper.state` 与 `ModuleState` 枚举（死代码）。
- 内部 `Wrapper[]` 改为 `List<Wrapper>`，去掉对 `ArrayExtensions.Append/Insert/Remove` 的依赖。

双数组同步修复方向：**只剩 `_moduleWrappers` 一份数据源**；`Modules` 属性由 `_moduleWrappers.Select(w => w.module)` 投影为只读列表。彻底消除不同步可能。

Priority 语义与排序稳定性：
- 运行时**不自动排序**，执行顺序 = `SetModules` 传入顺序 = 面板列表顺序。
- `Priority` 保留为**只读元数据**，仅用于 Editor "Sort by Priority" 按钮（稳定排序：同优先级保持原顺序）。
- 文档写明：VerticalPostureEvaluator 需要最先执行时，由用户在面板里排到最前（或 Runner 可选自动把它前置）。

`Wrapper.Update` 生命周期状态机（stepNum 0/1/2）**保留**，它是正确的 Start/Update/End 驱动，只清理掉无用的 `state` 字段。

### D.1 核心类测试（EditMode 为主）

**LocomotionCore**（重构后 API）：
- `SetModules` 后 `Modules` 顺序 == 传入顺序（回归旧 desync：断言 Modules 与实际驱动一致）。
- 生命周期顺序：spy 模块记录调用序，断言 Start→Update…Update→（禁用时）End。
- `enabled=false` 的模块不 Start；运行中 `DisableModule` 后下次 Update 触发 End；再 `EnableModule` 重新 Start。
- `SetModules(null/空)` 安全，Update 不崩。
- `Update()` 完整回路：给真实 Rigidbody 设初速，跑 Update，断言 `SynchronizeToRigidbody` 后 rb.velocity 被写回。

**TPhysics.Context**：
- `CurrentVelocity` set 更新 `CurrentSpeed/CurrentSquareSpeed` 并递增 `UpdatedCount`；`InvalidVelocity` 不更新。
- `SynchronizeToRigidbody` 写 velocity/MovePosition/MoveRotation；`SynchronizeFromRigidbody` 读回。
- `ResetUpdatedCount`；`OriginalInfo` 反映构造时 rb 状态。

**World**：
- Default 的 Up/Right/Forward = identity；`World(up, gravity)` 的 rotation = FromToRotation。
- `InverseTransformVector` 与 `TransformVector3` 互为逆（round-trip）。
- 自定义 Up 时 Right/Forward 由 rotation 推导。

**Locomotion.Context**：
- null groundDetector 构造抛异常。
- `groundNormal`：GroundsNormal==zero 回退 world.Up。
- `UpdatePlanes` 生成 ground/world 平面；`VerticalPosture` 默认 Holding。

**Ground / GroundDetector（纯逻辑部分）**：
- `Ground.MaxSlopeCos(deg)` 阈值正确（如 45°→cos45）。
- `GroundDetector.MaxSlope` clamp [0,90] 并重算 cos。
- `Enabled` 切换只在值变化时触发 `GroundingChanged`（订阅计数）。
- `GroundsNormal` 加权平均 + 忽略 invalid/null-obj 项（可用反射构造 Ground 或走 PlayMode）。
- `GroundDistance`：disabled / maxDistance<=0 / 无效位置 → -1（纯逻辑，无需物理）。

**VerticalPostureEvaluator**：
- `SampleQuantity` 重分配缓冲、`Enabled` 随样本量 0/非0 自动切换。
- 喂入全正/全负/全零竖直速度 → Ascending/Descending/Holding（直接调 OnUpdate 或设 CurrentVelocity）。
- 环形缓冲回绕正确。

**HorizontalLocomotion**：
- `DirectionVector` set 归一化；`MaxSpeed/AcceleratedSpeed` clamp ≥0。
- `Accelerate` 行为：`acceleratedSpeed==0` 时直接到 maxSpeed（不依赖 deltaTime）；正常路径钳制到 maxSpeed。

**BoostingLocomotion**：`OnStart` 清速度；`OnUpdate` 投影到 world.Up 平面。

**JumpLocomotion**：`OnStart` 按 `-2*g.y*h` 加竖直速度、timeline length=跳速/-g.y、Restart；`OnUpdate` 走 timeline；`OnEnd` Pause。

**StopLocomotion**：投影到 groundNormal。

**StopRotation**：`OnUpdate/OnStart/OnEnd` 都重置为 Original.Rotation。

**MutativeDrag**：`OnStart` 缓存 rbody + Restart；`OnUpdate` 按 NormalizedTime 在 range 间 Lerp；`OnEnd` 回 range.x。

**RotationByMouseOrTargetLocomotion**：camera==null 且无 target → 原样返回；有 target → 朝 target 转向（target 走 IPositionTarget mock）。

### D.2 PlayMode 物理集成场景

搭一个物理场景（可用 MCP 脚本建，或测试内 `GameObject.CreatePrimitive` 动态搭）：

- **地面**：一个 Box/Plane Collider，放在专用 "Ground" 层（测试 SetUp 里 `LayerMask.GetMask("Ground")` 或动态建层）。
- **角色**：一个带 Rigidbody（useGravity）+ Collider 的 GameObject，挂 Runner 或测试里直接 new LocomotionCore。
- **斜坡**：多个不同角度的斜板：
  - 平坡 0°（应 grounded，normal≈up）
  - 30°（MaxSlope=45° 时 grounded，normal≈坡面法线）
  - 45°（阈值边界）
  - 60°（> MaxSlope → 不 grounded）
- **墙/天花板**：验证不被算作支撑面（掩码/坡度过滤）。

断言思路：
- `IsGrounded` 在地面 true、悬空 false；`GroundsNormal` 平地为 up、斜坡为坡法线。
- `GroundDistance`：贴地 0、悬空射线命中=距离、超距=Infinity。
- 装配 HorizontalLocomotion 后，水平速度收敛到 MaxSpeed（阈值断言，允许误差）。
- JumpLocomotion：起跳后竖直速度 >0，随后落地 `GroundingChanged(true)`。
- MutativeDrag：drag 随 time 单调过渡到 range.y。
- Boosting：垂直分量被压平（≈0）。
- 掩码：把地面换到非掩码层 → 不 grounded。

### D.3 纯逻辑测不了、必须 PlayMode 的清单
1. GroundDetector 的 `OnCollisionEnter/Stay/Exit`（依赖真实 Collision 对象）。
2. `GroundDistance` 的 `Physics.Raycast` 命中/未命中。
3. 掩码匹配 `MatchesGroundMask`（依赖真实 layer + collision）。
4. LocomotionCore 驱动真实 Rigidbody 的完整运动/跳跃/贴地集成。
5. RotationByMouseOrTarget 的鼠标射线路径（依赖 Camera.ScreenPointToRay + Plane.Raycast）。
6. 任何依赖 `Time.deltaTime` 的数值行为（PlayMode 里时间真实流逝才可断言）。

### D.4 既有测试修复（测试 agent 顺带）
- 合并两个 `[SetUp]` 为一个。
- `LayerMask.NameToLayer("Terrain")` 改为 `1 << LayerMask.NameToLayer("Ground")`（先建 "Ground" 层）或 `LayerMask.GetMask`。
- 给 `Random`/`[Repeat]` 加 `Random.InitState(seed)` 或用固定序列。
- 新测试优先用重构后的 `SetModules` 而非旧 `AddModule_InsertByPriority`。
