# 状态机体系与使用

本文档描述 `MNAC.States` 的完整体系：分层结构、核心语义、Playable 过渡、回调状态、子状态机、动画桥接、Blueprint、Inspector 检视，以及典型用法和已知限制。

相关文档：

- [07_状态机复用方案A.md](07_状态机复用方案A.md)：Definition + Factory 的设计背景与实现细节。

## 1. 定位与设计原则

`MNAC.States` 是一套轻量、组合式的状态机库，命名空间统一为 `MNAC.States`。

设计原则：

1. **转移归机器，状态只管生命周期**：状态不持有转移表，转移由 `StateMachine<T>` 统一注册和清理。
2. **组合优先**：状态机本身实现 `IState<T>`，可以直接作为外层状态机的状态使用。
3. **显式驱动**：`Update(float deltaTime)` 由外部调用，可测、可支持 `FixedUpdate`。
4. **实例隔离**：每个状态实例持有自己的 Timeline/运行时数据，禁止跨机器共享。
5. **只读检视**：`IStateMachineInspection` 暴露快照，不反向修改状态机。

分层：

```text
Core（纯逻辑）
  ├── Playable（Timeline / 过渡）
  │     ├── WithCallback（委托生命周期）
  │     ├── SubStateMachine（子机包装）
  │     └── Animation（Animator/IK 桥接）
  ├── Blueprint（图描述 / 工厂）
  └── Inspection（只读快照）
        └── Editor（Inspector 矩阵）
```

程序集：

| 程序集 | 目录 | 职责 |
| --- | --- | --- |
| `MNAC.States` | `Assets/Scripts/States` | 运行时全部状态机代码 |
| `MNAC.Editor.States` | `Assets/Scripts/Editor/States` | 只读 Inspector |
| `MNAC.Utilities` | `Assets/Scripts/Utilities` | Timeline 等基础工具 |

`MNAC.States` 依赖 `MNAC.Utilities`；`MNAC.Editor.States` 只在 Editor 平台编译，依赖 `MNAC.States`。

## 2. Core 核心层

目录：`Assets/Scripts/States/Core`

### 2.1 类型一览

| 类型 | 作用 |
| --- | --- |
| `IState<T>` | 状态接口：名称、Id、Enabled、Context、OnEnter/OnUpdate/OnExit |
| `StateBase<T>` | 状态元数据基类，生命周期由子类实现 |
| `EmptyState<T>` | 生命周期全 no-op 的占位状态 |
| `StateMachine<T>` | 状态机核心，同时实现 `IState<T>` 以支持嵌套 |
| `Transition<T>` | 转移，持有触发条件与目标 |
| `StateMachineException` 及子类 | 生命周期/转移异常包装 |
| `ITransitionCondition<T>` | 带上下文的转移条件 |
| `DelegateTransitionCondition<T>` | 把 `Func<T,bool>` 适配成条件对象 |

### 2.2 `IState<T>`

```csharp
public interface IState<T>
{
    string Name { get; }
    Guid Id { get; }
    bool Enabled { get; set; }
    T Context { get; set; }

    void OnEnter();
    void OnUpdate(float deltaTime);
    void OnExit();
}
```

约定：

- `Name` 用于日志和 Inspector，不要求全局唯一，但同一台机器内建议唯一。
- `Id` 是实例唯一标识。
- `Enabled=false` 的状态不能作为转移目标；转移求值时会被跳过。
- `Context` 由 `StateMachine<T>.AddState` 注入，赋值 `StateMachine.Context` 会广播给所有已注册状态。

### 2.3 `StateMachine<T>` 生命周期

```csharp
public virtual void Update(float deltaTime)
{
    if (!enabled) return;

    if (current == null)
    {
        EnterInitialState();   // 初始状态：SetInitialState 指定的，或首个 AddState 的
        if (current == null) return;
    }

    var transition = Evaluate(current);   // 按注册顺序找第一条满足条件的出边
    if (transition != null)
        ApplyTransition(transition);      // 默认直切

    current?.OnUpdate(deltaTime);
}
```

切换顺序：

```text
previous.OnExit()
current = next
next.OnEnter()
```

关键语义：

- `current` 在 `OnEnter` 之前提交，因此 `OnEnter` 内可以安全读取 `CurrentState`。
- `OnEnter` 抛异常时 `current` 会被置空，避免机器指向一个已经 Exit、但没有 Enter 成功的状态。
- `OnExit` 抛异常会包装成 `StateExitException`，不会继续切换。
- 初始状态未显式设置时，取第一个 `AddState` 的状态。
- 没有任何状态时，`Update` 直接返回。

### 2.4 状态注册

```csharp
public void AddState(IState<T> state);
public void AddState(string key, IState<T> state);
public bool RemoveState(IState<T> state);
public bool Contains(IState<T> state);

public IState<T> FindState(string key);   // 找不到返回 null
public IState<T> GetState(string key);    // 找不到抛 StateKeyNotFoundException
public IReadOnlyDictionary<string, IState<T>> StatesByKey { get; }
```

规则：

- 无 key 的 `AddState` 保持旧行为，重复注册 no-op。
- key 必须非空，同一台机器内唯一；一个状态实例只能挂一个 key。
- key 重复且指向不同状态时抛 `DuplicateStateKeyException`。
- `RemoveState` 会：
  - 如果移除的是当前状态，先调用 `OnExit`；
  - 从状态列表移除；
  - 清理所有以它为源或目标的转移；
  - 清理它的所有 key；
  - 如果它是初始状态，清空初始状态。
- `States` / `Transitions` / `StatesByKey` 都是只读视图，运行时不要直接修改底层列表。

### 2.5 初始状态与切换

```csharp
public void SetInitialState(IState<T> state);
public void SetInitialState(string key);

public void ChangeStateTo(IState<T> state);
public void ChangeStateTo(string key);
```

- `SetInitialState` 要求状态已注册，否则抛 `StateNotRegisteredException`。
- `ChangeStateTo` 会走完整校验和 `OnExit/OnEnter`。
- 自转移（源 == 目标）统一 no-op：不会触发 `OnExit/OnEnter`，只会执行 `OnTriggered`（如果有）。

### 2.6 转移注册

```csharp
public Transition<T> AddTransition(
    IState<T> source,
    IState<T> destination,
    Func<bool> trigger = null,
    Action<T> onTriggered = null);

public void AddTransition(Transition<T> transition);

public bool RemoveTransition(Transition<T> transition);
public void ClearTransitionsFrom(IState<T> source);
```

- `source` / `destination` 必须已注册，否则抛 `StateNotRegisteredException`。
- `AddTransition(Transition<T>)` 用于注册自定义转移（Blueprint 和 Playable 层使用）。
- `CreateTransition` 是 protected virtual，子类可重写以创建特定转移类型。
- `RegisterTransition` 是 protected，做注册校验后加入列表。

### 2.7 触发条件

`Transition<T>` 同时支持两类条件，二者之间是 **AND**：

```csharp
public IReadOnlyList<Func<bool>> Triggers { get; }
public IReadOnlyList<ITransitionCondition<T>> Conditions { get; }
public int TriggerCount { get; }
public bool HasTriggerConditions { get; }

public bool IsTriggered { get; }          // 等价于 Evaluate(default)
public bool Evaluate(T context);          // 状态机内部统一走这个
```

语义：

- 没有任何条件 = 无条件转移，恒触发。
- 多个条件按顺序短路求值，全部为 true 才触发。
- `LastTriggerResult` / `HasTriggerResult` 是调试遥测；每次 `Evaluate` 都会重新求值，不是跨帧缓存。
- 依赖 Context 的条件必须走 `Evaluate(context)`。旧的无参 `IsTriggered` 会传入 `default(T)`。
- 条件抛异常时，由状态机包装成 `StateTransitionException`。

带上下文的写法：

```csharp
var transition = machine.AddTransition(idle, run, () => true);
transition.AddCondition(new DelegateTransitionCondition<Context>(
    ctx => ctx.Speed > 0.1f));
```

### 2.8 求值与应用

```csharp
protected virtual Transition<T> Evaluate(IState<T> state)
{
    foreach (var transition in transitions)
    {
        if (transition.Source != state) continue;
        if (!transition.Destination.Enabled) continue;
        if (transition.Evaluate(context)) return transition;
    }
    return null;
}
```

- 按注册顺序返回第一条满足条件的转移。
- 目标状态必须 `Enabled`。
- `ApplyTransition` 默认直切：
  - 自转移：只调用 `OnTriggered`，不切换；
  - 普通转移：先调用 `OnTriggered`，再 `ChangeState`。
- `OnTriggered` 在状态切换前执行，异常会包装成 `StateTransitionException`。

### 2.9 作为嵌套状态

`StateMachine<T>` 实现 `IState<T>`：

- `OnEnter`：
  - 如果当前没有子状态，进入自己的初始状态；
  - 如果已有子状态，转发 `current.OnEnter()`，不会重新进入初始状态。
- `OnUpdate`：等价于 `Update(deltaTime)`。
- `OnExit`：退出当前子状态并清空，下次进入重新从初始态开始。

因此，嵌套状态机可以作为外层的一个普通状态直接 `AddState`。

### 2.10 异常

| 异常 | 触发场景 |
| --- | --- |
| `StateNotRegisteredException` | 状态未注册就添加转移/切换/设初始态 |
| `StateEnterException` | `OnEnter` 抛异常 |
| `StateExitException` | `OnExit` 抛异常 |
| `StateUpdateException` | `OnUpdate` 抛异常 |
| `StateTransitionException` | 条件求值、`OnTriggered`、转移应用抛异常 |
| `DuplicateStateKeyException` | 同一 key 注册给不同状态 |
| `StateKeyNotFoundException` | 按 key 查找失败 |
| `StateMachineException` | 基类/通用错误 |

所有异常消息都带状态名或 key，便于定位。

### 2.11 最小示例

```csharp
public sealed class PlayerContext
{
    public float Speed;
    public bool Grounded;
}

public sealed class IdleState : StateBase<PlayerContext>
{
    public IdleState() : base("Idle") { }

    public override void OnEnter() { /* 播放待机 */ }
    public override void OnUpdate(float deltaTime) { }
    public override void OnExit() { /* 停止待机 */ }
}

var context = new PlayerContext();
var machine = new StateMachine<PlayerContext>("Player");
var idle = new IdleState();
var run = new EmptyState<PlayerContext>("Run");

machine.AddState(idle);
machine.AddState(run);
machine.SetInitialState(idle);
machine.AddTransition(idle, run, () => context.Speed > 0.1f);

machine.Context = context;
machine.Update(Time.deltaTime);
```

## 3. Playable 层

目录：`Assets/Scripts/States/Playable`

Core 只做直切。Playable 层把“切换”做成一个临时过渡状态，播放转移自己的 Timeline。

### 3.1 `PlayableStateBase<T>`

```csharp
public abstract class PlayableStateBase<T> : StateBase<T>, IPlayableState<T>
{
    protected ITimeline timeline;

    public virtual ITimeline Timeline => timeline;

    public override void OnEnter()  => timeline?.Restart();
    public override void OnUpdate(float deltaTime) => timeline?.OnUpdate(deltaTime);
    public override void OnExit()
    {
        if (timeline != null && timeline.IsRunning)
            timeline.End();
    }
}
```

约定：

- 每个状态实例在构造时创建自己的 Timeline。
- `OnEnter` 重启 Timeline，`OnUpdate` 推进，`OnExit` 在仍在运行时结束。
- 子类可以重写 `NewTimeline(float duration)` 返回自定义 Timeline；过渡状态会返回 `null` 以完全接管。
- 六个过渡回调默认空实现：
  - `FromPreviousStateTransitionBegin/Running/End`
  - `ToNextStateTransitionBegin/Running/End`

### 3.2 `PlayableTransition<T>`

```csharp
public class PlayableTransition<T> : Transition<T>, IPlayableTransition<T>
{
    public ITimeline Timeline { get; }
    public InterruptionMode InterruptionMode { get; }
}
```

构造时：

1. 创建 `Timeline(duration)`。
2. 如果有 `durationEvent`，挂到 `[0,1]` 区间事件，逐帧回调。
3. 挂六个过渡事件：
   - 源状态 `ToNextStateTransitionBegin/Running/End`
   - 目标状态 `FromPreviousStateTransitionBegin/Running/End`

`IReadonlyPlayableTransition<T>` 只暴露 `Timeline` 和 `InterruptionMode`，用于回调参数；`IPlayableTransition<T>` 额外暴露 `Source` / `Destination`。

### 3.3 `PlayableStateMachine<T>`

构造：

```csharp
var machine = new PlayableStateMachine<Context>("Player");
```

添加转移：

```csharp
// 完整版：时长 + 逐帧回调 + 打断模式
PlayableTransition<Context> AddTransition(
    IPlayableState<Context> source,
    IPlayableState<Context> destination,
    float duration = 0,
    Func<bool> trigger = null,
    Action<IPlayableState<Context>, IPlayableState<Context>, float> durationEvent = null,
    InterruptionMode interruptionMode = InterruptionMode.Next);

// 旧版简写：也会创建 PlayableTransition（零时长）
Transition<Context> AddTransition(
    IState<Context> source,
    IState<Context> destination,
    Func<bool> trigger = null,
    Action<Context> onTriggered = null);
```

`CreateTransition` 会校验源/目标都实现 `IPlayableState<T>`，否则抛 `InvalidCastException`。

### 3.4 过渡执行路径

`PlayableStateMachine.Update`：

```text
if current is TransitionState:
    AdvanceTransition(ts, deltaTime)
    return

base.Update(deltaTime)          // 求值、启动过渡、或直切
if current is TransitionState started:
    CompleteTransitionIfDone(started)   // 处理零时长过渡
```

`ApplyTransition`：

- 自转移：只 `OnTriggered`。
- 目标是可播放转移且 Timeline 非空：
  - `transitionState.Configure(this, playableTransition)`
  - `SwitchTo(transitionState)`
- 否则直切。

`TransitionState` 的行为：

- 名字为 `"源 -> 目标"`。
- 持有当前转移的 Timeline。
- `IsComplete` 用 `NormalizedTime >= 1` 判断。
- `OnUpdate` 推进 Timeline；如果已经到 1 但 Timeline 还没吐 End，会补一拍 `OnUpdate(0)`。
- 完成时：`ChangeState(destination)`，然后对目标状态执行 `OnUpdate(0)`，不重复喂本帧 delta。
- 被打断时：
  - `InterruptionMode.None`：不允许目标状态的出边打断。
  - `InterruptionMode.Next`：目标状态上带条件的出边可以打断当前过渡，改道新目标。
- `OnExit`：未完成则中断并结束 Timeline；已完成则只 End，避免二次触发 End 回调。

过渡期间 `CurrentState` 是内部 `TransitionState`，不是目标状态。外部若只想判断“是否在过渡”，应使用 `IStateMachineInspection.IsTransitioning`，不要拿 `CurrentState` 和目标状态比较。

### 3.5 零时长过渡

所有 `PlayableTransition` 都有非空 Timeline，即使 `duration == 0`。

- 第一次 `Update` 进入过渡状态；
- `CompleteTransitionIfDone` 在同一帧检测到完成；
- 目标状态收到一次 `OnUpdate(0)`。

所以零时长过渡不会额外占用一帧，但会走完整的过渡回调。

### 3.6 示例

```csharp
public sealed class PlayerContext
{
    public float Speed;
    public bool Jump;
}

public sealed class IdleState : PlayableStateBase<PlayerContext>
{
    public IdleState() : base("Idle", 1f) { }
}

public sealed class RunState : PlayableStateBase<PlayerContext>
{
    public RunState() : base("Run", 1f) { }
}

var context = new PlayerContext();
var machine = new PlayableStateMachine<PlayerContext>("Player");
var idle = new IdleState();
var run = new RunState();

machine.AddState(idle);
machine.AddState(run);
machine.SetInitialState(idle);
machine.Context = context;

machine.AddTransition(
    idle,
    run,
    duration: 0.2f,
    trigger: () => context.Speed > 0.1f,
    durationEvent: (source, destination, t) => { /* 0..1 混合 */ });

machine.Update(Time.deltaTime);
```

### 3.7 Blending 过渡

`BlendingTransition<T>` 在 `PlayableTransition<T>` 上增加：

- `offset`：目标 Timeline 从中间开始播，开头段被跳过。
- `fixedExitTime`：源状态播到指定归一化时刻强制触发。
- `BlendingTransitionOptions`：可序列化配置。

构造要求源和目标都是 `IWithCallbackPlayableState<T>`，因为它需要在目标状态退出时恢复 Timeline 长度。

行为：

- 过渡开始时，解析真正的 Timeline 所有者：
  - 如果目标实现 `IPlayableStateTimelineOwner<T>` 且 `TimelineOwner != null`，用子状态；
  - 如果目标是 `StateMachine<T>`，用 `CurrentState as IWithCallbackPlayableState<T>`；
  - 否则用目标自身。
- 把目标 Timeline 长度缩短为：

```text
newLength = max(0, oldLength - (offset + transitionDuration))
```

- 目标状态 `ExitAction` 挂恢复逻辑，退出时恢复原长度。
- 过渡被中断时，`OnInterrupted()` 恢复目标长度。
- `fixedExitTime` 会额外添加一个触发器：

```csharp
AddTrigger(() => PlayableSource.Timeline.NormalizedTime >= fixedExitTime);
```

`SubStateMachineTransition<T>` 是 `BlendingTransition<T>` 的子类，用于“从外部状态进入子状态机的某个指定状态”：

- 过渡开始时先确保子机已进入；
- 把子机切到 `destinationState`；
- 再调用 `base.Begin`，让 Blending 作用到新目标的 Timeline 上。

### 3.8 Timeline 归属

包装型状态（`PlayableStateMachineState`、`WithCallbackStateMachineState`、`SubStateMachineState`）的外部 `Timeline` 指向子机当前状态，而不是包装层自己的 Timeline。

原因是 Blending 需要缩短/订阅真正的子状态 Timeline。实现通过 `IPlayableStateTimelineOwner<T>` 暴露：

```csharp
public interface IPlayableStateTimelineOwner<T>
{
    IWithCallbackPlayableState<T> TimelineOwner { get; }
}
```

注意：包装层基类仍然会创建并推进自己的 Timeline，但外部通过 `Timeline` 属性看到的是子机 Timeline。Blending 使用 `TimelineOwner` 解析，不会误用包装层 Timeline。

## 4. 回调状态层

目录：`Assets/Scripts/States/WithCallback`

### 4.1 `IWithCallbackPlayableState<T>`

```csharp
public interface IWithCallbackPlayableState<T> : IPlayableState<T>
{
    Action EntryAction { get; set; }
    Action UpdateAction { get; set; }
    Action ExitAction { get; set; }
}
```

### 4.2 `WithCallbackPlayableState<T>`

生命周期顺序：

```text
OnEnter:
  EntryAction
  base.OnEnter()    // Timeline.Restart

OnUpdate:
  UpdateAction
  base.OnUpdate()   // Timeline.OnUpdate

OnExit:
  base.OnExit()     // Timeline.End（如果还在运行）
  ExitAction
```

适合不想为每个状态写子类、只想挂委托的场景。

### 4.3 `WithCallbackPlayableStateMachine<T>`

在 `PlayableStateMachine<T>` 上增加同样的三个委托：

```text
OnEnter:
  EntryAction
  base.OnEnter()

OnUpdate:
  UpdateAction
  base.OnUpdate()

OnExit:
  base.OnExit()
  ExitAction
```

它同时实现 `IWithCallbackPlayableState<T>`，因此可以被外层机器当作状态使用。

示例：

```csharp
var machine = new WithCallbackPlayableStateMachine<Context>("Enemy");
machine.EntryAction = () => { /* 进入战斗 */ };
machine.UpdateAction = () => { /* 每帧 AI */ };
machine.ExitAction = () => { /* 退出战斗 */ };
```

## 5. 子状态机

目录：`Assets/Scripts/States/SubStateMachine`

子状态机的作用：把一台已经构建好的状态机包装成一个普通状态，供外层状态机使用。

### 5.1 三种包装

| 类型 | 包装对象 | 进入行为 |
| --- | --- | --- |
| `PlayableStateMachineState<T>` | `PlayableStateMachine<T>` | 子机未初始化时进入初始态；否则转发当前子状态 `OnEnter` |
| `WithCallbackStateMachineState<T>` | `WithCallbackPlayableStateMachine<T>` | 同上 |
| `SubStateMachineState<T>` | `WithCallbackPlayableStateMachine<T>` + 目标状态 | 确保子机进入，然后切到指定目标状态 |

三者都实现：

- `IPlayableStateTimelineOwner<T>`：`TimelineOwner = stateMachine.CurrentState as IWithCallbackPlayableState<T>`
- 外部 `Timeline` 返回 `stateMachine.Timeline`
- 六个过渡回调全部转发给子机

### 5.2 `SubStateMachineState<T>`

```csharp
var child = new WithCallbackPlayableStateMachine<Context>("Child");
var idle = new IdleState();
var run = new RunState();
child.AddState(idle);
child.AddState(run);
child.SetInitialState(idle);

var wrapper = new SubStateMachineState<Context>(child, run, "RunSub");
outer.AddState(wrapper);
```

进入 `wrapper` 时：

1. `base.OnEnter()`；
2. `EnsureMachineEntered()`（子机未进入则 `OnEnter`）；
3. `child.ChangeStateTo(targetState)`。

目标状态必须已注册在子机中，否则构造时抛 `StateNotRegisteredException`。

### 5.3 `SubStateMachineTransition<T>`

用于“从外层状态直接进入子机某个状态”，支持 Blending：

```csharp
var transition = new SubStateMachineTransition<Context>(
    sourceState,
    childMachine,
    destinationState,
    trigger: () => context.Alerted,
    duration: 0.2f,
    offset: 0.1f);

outer.AddTransition(transition);
```

进入时：

1. `ResetIfActive()` 恢复上一次可能缩短的 Timeline；
2. 确保子机已进入；
3. `child.ChangeStateTo(destinationState)`；
4. `base.Begin` 对新的目标状态应用缩短。

### 5.4 限制

当前包装方式接收的是**已经构建好的状态机实例**，不是“定义”：

- 同一个子机实例被多个外层状态复用时，内部 `CurrentState` 会共享；
- 每次进入不会重新构建子机；
- 如果需要“每次进入一份独立子机”，需要方案 D 的 `SubStateMachineDefinition<T>`，它持有 Blueprint，在 `OnEnter` 时 `Build` 新实例。

## 7. Blueprint 图描述层

目录：`Assets/Scripts/States/Blueprint`

目标：把“图结构”和“运行实例”分开，一份 Blueprint 可以 `Build` 多次，每次得到独立状态机。

### 7.1 类型

| 类型 | 作用 |
| --- | --- |
| `ITransitionCondition<T>` | 带 Context 的转移条件 |
| `DelegateTransitionCondition<T>` | `Func<T,bool>` 适配器 |
| `TransitionSpec<T>` | 一条转移的 key、条件、Playable 参数 |
| `StateMachineBlueprintBase<T, TMachine, TSelf>` | 图描述基类 |
| `StateMachineBlueprint<T>` | 构建 `StateMachine<T>` |
| `PlayableStateMachineBlueprint<T>` | 构建 `PlayableStateMachine<T>` |

非泛型薄壳：

- `StateMachineBlueprint` = `StateMachineBlueprint<object>`
- `PlayableStateMachineBlueprint` = `PlayableStateMachineBlueprint<object>`

### 7.2 核心 API

```csharp
public TSelf State(string key, Func<IState<T>> factory);
public TSelf State<TState>(string key) where TState : IState<T>, new();

public TSelf Transition(
    string from,
    string to,
    ITransitionCondition<T> condition = null,
    Action<T> onTriggered = null);

public TSelf Transition(
    string from,
    string to,
    Func<T, bool> condition,
    Action<T> onTriggered = null);

public TSelf Entry(string key);

public TMachine Build(T context);
```

Playable 额外提供：

```csharp
public PlayableStateMachineBlueprint<T> PlayableTransition(
    string from,
    string to,
    float duration = 0f,
    ITransitionCondition<T> condition = null,
    Action<IPlayableState<T>, IPlayableState<T>, float> durationEvent = null,
    InterruptionMode interruptionMode = PlayableTransition<T>.INTERRUPTION_MODE_DEFAULT,
    Action<T> onTriggered = null);

public PlayableStateMachineBlueprint<T> PlayableTransition(
    string from,
    string to,
    float duration,
    Func<T, bool> condition,
    ...);
```

### 7.3 Build 流程

```text
1. CreateMachine()
2. machine.Context = context
3. 按注册顺序执行 state factory，AddState(key, state)
4. 按 key 解析每条转移的源/目标
5. 创建转移，挂条件与 OnTriggered，注册
6. 设置 Entry 初始状态
7. 返回 machine
```

规则：

- 每次 `Build` 都会重新执行所有状态工厂。
- Blueprint 不持有任何状态/转移/Timeline 实例。
- 状态工厂返回 `null` 抛 `StateMachineException`。
- key 为空抛 `ArgumentException`。
- 重复 key 抛 `DuplicateStateKeyException`。
- 转移或 Entry 引用不存在的 key 抛 `StateKeyNotFoundException`。
- 未设置 Entry 时，首个注册状态作为初始状态。
- Build 不是线程安全的，配置完成后应视为只读。

### 7.4 实例隔离

必须遵守：

1. 工厂每次 Build 返回新状态实例。
2. 不要在工厂里返回共享单例。
3. Playable 状态构造时创建 Timeline，更不能跨机器共享。
4. Blueprint 本身不缓存实例。

错误示例：

```csharp
var shared = new IdleState();
var blueprint = new PlayableStateMachineBlueprint<Context>("Bad")
    .State("idle", () => shared);   // 两台机器会共享同一 Timeline
```

正确示例：

```csharp
.State("idle", () => new IdleState())
```

### 7.5 示例

```csharp
public sealed class EnemyContext
{
    public float Distance;
    public bool Alerted;
}

var blueprint = new PlayableStateMachineBlueprint<EnemyContext>("Enemy")
    .State("idle", () => new IdleState())
    .State("chase", () => new ChaseState())
    .Entry("idle")
    .PlayableTransition("idle", "chase", 0.2f, ctx => ctx.Alerted)
    .PlayableTransition("chase", "idle", 0.25f, ctx => !ctx.Alerted);

var aggressive = blueprint.Build(new EnemyContext { Alerted = true });
var passive = blueprint.Build(new EnemyContext { Alerted = false });
```

两台机器共享同一份图描述，但状态、转移、Timeline、Context 全部独立。

### 7.6 与方案 D 的关系

Blueprint 是方案 D 的基础：

- D 的 `SubStateMachineDefinition<T>` 持有 `Graph`（Blueprint）；
- 进入子状态时 `Graph.Build(context)` 得到独立子机；
- 退出时丢弃，下一次进入重新构建。

当前 `SubStateMachineState<T>` 接收的是已构建实例，不具备这个能力。

目录：`Assets/Scripts/States/Inspection` 与 `Assets/Scripts/Editor/States`

### 8.1 `IStateMachineInspection`

```csharp
public interface IStateMachineInspection
{
    string Name { get; }
    bool Enabled { get; }
    string CurrentStateName { get; }

    IReadOnlyList<StateSnapshot> StateSnapshots { get; }
    IReadOnlyList<TransitionSnapshot> TransitionSnapshots { get; }

    bool IsTransitioning { get; }
    string ActiveTransitionSource { get; }
    string ActiveTransitionDestination { get; }

```

`StateSnapshot`：

- `Name`
- `TypeName`
- `Enabled`
- `IsCurrent`

`TransitionSnapshot`：

- `SourceName`
- `DestinationName`
- `Duration`
- `InterruptionMode`
- `TriggerCount`
- `HasTriggerResult`
- `LastTriggerResult`
- `IsActive`
- `Progress`
- `IsPlayable`（时长 > 0 或打断模式非 None）

`StateMachine<T>` 显式实现该接口，因此可以：

```csharp
var inspection = (IStateMachineInspection)machine;
```

### 8.2 `StateMachineHost`

```csharp
public abstract class StateMachineHost : MonoBehaviour
{
    public abstract IStateMachineInspection Inspection { get; }
    protected abstract void Tick(float deltaTime);

    protected virtual void Update()
    {
        if (!isActiveAndEnabled) return;
        Tick(Time.deltaTime);
    }
}
```

自定义宿主只需要：

1. 创建并持有状态机；
2. `Inspection` 返回状态机；
3. `Tick` 调用 `machine.Update(deltaTime)`。

### 8.3 `StateMachineHostEditor`

`[CustomEditor(typeof(StateMachineHost), true)]`，只读，不修改状态机。

内容：

- 标题：状态机名、状态数、转移数
- 当前状态、Enabled
- 转移矩阵（行 → 列）
- 选中转移详情
- 当前过渡进度条
- 当前状态的出边及上次条件求值结果
- 宿主字段折叠面板

矩阵限制：

- 超过 8 个状态，或单元格宽度不足时，退化为转移列表。
- 同一对 source/destination 有多条转移时，矩阵只显示第一条（`Find` 按列表顺序返回第一个）。
- 自转移显示 `—`，不展示。
- 状态名超过 7 个字符会截断。
- 运行时 10Hz 刷新；非运行时靠 Inspector 重绘。

## 10. 规则与坑

### 10.1 状态实例不能共享

- `PlayableStateBase` 在构造时创建 Timeline；
- Timeline 有运行状态、时间和事件游标；
- 两台机器共享同一个状态实例会导致时间轴互相污染。

Blueprint 的工厂必须每次返回新实例。

### 10.2 Context 的赋值时机

`StateMachine.Context` 的 setter 会广播给所有已注册状态：

```csharp
public virtual T Context
{
    get => context;
    set
    {
        context = value;
        foreach (var state in states)
            state.Context = value;
    }
}
```

- 建议在 `AddState` 前设置，或 setup 阶段统一设置。
- 运行时频繁改 Context 会有 O(状态数) 开销。
- 状态内部不要缓存 `Context` 引用并假设它永远不变。

### 10.3 `IsTriggered` 与 `Evaluate(context)`

- `IsTriggered` 是旧 API，传 `default(T)`。
- 依赖 Context 的条件必须用 `Evaluate(context)`。
- 状态机内部已经统一走 `Evaluate(context)`。
- `LastTriggerResult` 只记录最后一次求值，不保证和当前帧完全同步（取决于谁调用了 `Evaluate`）。

### 10.4 触发器副作用

- 每次 `Evaluate` 都会重新调用所有条件，遇到 false 短路。
- 如果条件有副作用（计数、改状态），要自己保证幂等。
- 不要依赖“缓存结果避免重复调用”——`LastTriggerResult` 只是遥测。

### 10.5 自转移

- 源 == 目标时不会 `OnExit/OnEnter`。
- 只会执行 `OnTriggered`。
- 需要“重进状态”的逻辑必须显式 `ChangeStateTo` 到别的状态再回来，或自己调用生命周期。

### 10.6 过渡期间不要用 CurrentState 判断目标

- 过渡期间 `CurrentState` 是内部 `TransitionState`。
- 判断是否在过渡用 `IStateMachineInspection.IsTransitioning`。
- 判断目标用 `ActiveTransitionDestination`。

### 10.7 过渡中外部切换

`ChangeStateTo` 在过渡期间调用会触发 `TransitionState.OnExit`，结束旧 Timeline，再进入新状态。

### 10.8 Blending 的类型要求

- `BlendingTransition<T>` 的源和目标必须是 `IWithCallbackPlayableState<T>`。
- 普通 `PlayableStateBase<T>` 不实现该接口，不能直接用于 Blending。
- 包装型状态（`PlayableStateMachineState` 等）实现了该接口，可以用。

### 10.9 子状态机目标必须已注册

`SubStateMachineState<T>` 和 `SubStateMachineTransition<T>` 构造时会检查目标状态是否在子机中，未注册抛 `StateNotRegisteredException`。

### 10.10 矩阵不区分重复边

同一对 source/destination 有多条转移时，Inspector 矩阵只显示第一条。需要看全部转移时，使用转移列表或自定义检视。

### 10.11 包装层 Timeline

包装型状态的 `Timeline` 属性返回子机 Timeline，但基类仍会创建并推进自己的 Timeline。做 Blending 时以 `IPlayableStateTimelineOwner.TimelineOwner` 为准。

### 10.12 动画层只做桥接

`AnimationStateMachine` 不负责播放动画，只负责：

- 保存当前 `AnimationStateBase`；
- 转发 `OnAnimatorIK`；
- `Enabled` 门控。

动画播放、参数、Transition 仍需在状态内部实现。

## 11. 扩展点

### 11.1 自定义状态

继承 `StateBase<T>` 或 `PlayableStateBase<T>`：

```csharp
public sealed class DeadState : PlayableStateBase<Context>

    public DeadState() : base("Dead", 1f) { }

    public override void OnEnter() { base.OnEnter(); /* ... */ }
    public override void OnUpdate(float dt) { base.OnUpdate(dt); /* ... */ }
    public override void OnExit() { /* ... */ base.OnExit(); }
}
```

### 11.2 自定义转移

继承 `Transition<T>` 或 `PlayableTransition<T>`，通过 `AddTransition(Transition<T>)` 注册。

### 11.3 自定义状态机

继承 `StateMachine<T>`，重写：

- `CreateTransition`：自定义转移类型；
- `ApplyTransition`：自定义切换路径；

```csharp
public sealed class DistanceCondition : ITransitionCondition<EnemyContext>

}
```

继承 `StateMachineHost`，实现 `Inspection` 和 `Tick`，即可复用转移矩阵 Inspector。

## 14. 已知限制

1. **没有序列化 Blueprint**：`StateMachineBlueprint` 是纯 C# 对象，不能直接存成资产。
2. **没有图编辑器**：目前只有 Inspector 转移矩阵。
3. **矩阵最多 8 个状态**，且同一对 source/destination 只显示第一条转移。
4. **没有条件描述**：Inspector 只显示条件数量，不显示条件内容。
5. **子状态机不是按定义构建**：包装的是已构建实例，不能每次进入重新建一份。
6. **状态实例共享风险**：库不阻止共享，需要调用方遵守。
7. **动画层很薄**：只做 Animator 引用和 IK 转发，不负责播放。
8. **Blueprint 的 key 是字符串**：拼写错误只能运行时发现。

后续方向：

- 方案 D：`SubStateMachineDefinition<T>` + 每次进入 `Build` 独立子机；
- 强类型 key / 转移 builder；
- Blueprint 静态图 / Mermaid 导出；
- ScriptableObject 图资产与 GraphView 编辑器（需要先解决条件序列化）。
